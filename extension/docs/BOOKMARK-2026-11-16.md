## 18 November: cross-context decisions and immutable review choices

CodeRabbit's review of `ed15964` found two further correctness gaps despite green CI: page restore could erase a concurrent worker addition, and a selected destination could attach to a replacement resource after Preview. The candidate now uses one same-origin Web Lock across all page/worker decision writers. Reads, live validation, hashing, serialization and writes occur inside that lock. Foreground changes are explicit upserts and conditional removals against the expected resource/parent, never replacement of a stale whole UI snapshot. Hash failures abort without overwriting pending records.

Single and bulk confirmation capture immutable reviewed identities and chosen paths before waiting for the bookmark mutation lock. Preview and the actual storage listener clear selections when resource or parent changes, retaining unchanged choices. Bookmark mutation locks are acquired before decision-store locks, never in reverse. Chrome bookmark moves still require the existing durable journal: Web Locks are coordination, not rollback.

Fresh verification before the final candidate commit: all 22 native suites pass, including 9 deterministic decision-race regressions, 7 identity tests and 8 evidence tests. Independent read-only runtime review found no blocking defect. The new real Chromium page/worker race journey is committed for CI acceptance; its result must be recorded separately. No owner data, live inference or Mac memory was tested. These fixes do not establish semantic sorting accuracy or make ambiguous links safe to file automatically.

Research checked 18 November:

- [Web Locks specification](https://www.w3.org/TR/web-locks/) and [Chrome storage](https://developer.chrome.com/docs/extensions/reference/api/storage): shared asynchronous storage has no documented object CAS transaction; use a common lock covering the whole read/validate/write operation. Worker/page termination releases a lock but does not undo completed bookmark moves.
- [MV3 lifecycle](https://developer.chrome.com/docs/extensions/develop/concepts/service-workers/lifecycle): worker globals are not durable. Keep the existing persistent queue and pre-move journal.
- [super-bookmarks](https://github.com/jochiang/super-bookmarks) offers local MiniLM/WASM search inspiration (~23 MB first download per README, not measured RAM). MIT is claimed but the license API was unresolved; maintenance and filing accuracy are not established. No code adopted.
- [mindmark](https://github.com/sukanth/mindmark) has an MIT license and local ONNX indexing (~130 MB model claim), but direct profile-file/Python CLI access is unsuitable for this Chrome workflow. No code adopted.
