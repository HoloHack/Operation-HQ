# Operation HQ — audit and recovery plan

Audit date: 29 September 2026. Baseline dashboard commit: `90ee01bf5407acd644faef0483361cf2a19a7f62`. Roadmap: v3, file version 15 (20 September 2026). This is a source-backed dashboard audit plus a roadmap-backed extension inventory, not certification of every extension feature.

## Executive assessment

The product has a useful foundation, but it is not complete. The split removed Operation HQ's UI from ordinary new tabs; it did not migrate the whole extension into the web dashboard. The two surfaces have substantially different capabilities. The historical 75% figure is an engineering estimate without a reproducible weighting method, not a verified completion rate.

The highest risks are persistence correctness, the automatic browser-data bridge, misleading capability/saving labels, and insufficient end-to-end verification. More decorative animation, another database, or a more expensive language model would not fix these problems.

## Evidence and scope

- Read all product dashboard source: `app/dashboard.tsx`, `app/page.tsx`, `app/api/state/route.ts`, `app/chatgpt-auth.ts`, `lib/hq-state.ts`, CSS, schema, migration and package/configuration files.
- Recovered the source repository and checked its clean baseline. The published Site reports version 1.
- Baseline TypeScript check fails with eight unknown-response type errors.
- Read all 604 lines of the canonical roadmap. Its older sections still contradict the split architecture.
- Extension archive version 7 is identified, but three download attempts returned HTTP 502. Extension implementation and old passing-suite claims are not independently verified in this audit.
- Production access currently reports **public**, changed 22 September. User state endpoints still require authentication. Public shell access is not evidence that personal database records are publicly readable. Preserve the configured audience; fix the anonymous experience instead of silently changing sharing.
- No supported browser-control skill is available in this run. Browser visuals, real Chrome APIs, OAuth, and Mac memory measurements remain release gates, not assumed passes.

## Inherent design limits and decisions

1. **Perfect bookmark meaning is unknowable from arbitrary URLs.** Ambiguous bookmarks must remain in place or receive a user correction. Removing a review queue cannot justify random filing. Preserve folders and tabs; never delete for appearance.
2. **A browser extension is not an operating-system agent.** Downloads API metadata is not unrestricted filesystem access. Assessment import must be chosen/authorized and validated. Unsupported social messages remain official links.
3. **AI capability and action authority are separate.** A model may propose a plan, but typed tools validate it, show effects and require approval. A larger model can exceed the memory budget; do not load it into every tab.
4. **A full-resolution cinematic effect costs GPU memory.** More layers are not automatically better. Cap pixel ratio, visible frame rate and blur layers; stop work when hidden; make motion opt-out equivalent in meaning.
5. **Cross-device notes require conflict UX, not “last write wins” slogans.** Offline guarantees need an account-scoped durable outbox, recoverable conflicts and deletion semantics. Current cloud row is not end-to-end encrypted.
6. **GitHub/Supabase are not fixes by themselves.** Existing Git history and D1 already serve source control and persistence. Keep them during recovery. Add GitHub CI when a verified repository connection is available; use Supabase only for a concrete capability that justifies migration.

## Delivery sequence and acceptance gates

### Stage A — protect work (this repair pass)
Serialize saves, preserve concurrent drafts, fail closed on corrupt data, fix request validation, make browser import explicit and stop unreviewed writeback. Gate: delayed-response, conflict, malformed-input and storage-failure tests.

### Stage B — restore dependable daily use (this repair pass)
Fix focus pause/background behavior, chapter idempotency, unknown-command honesty, dialog keyboard behavior, motion preference, padding and weather recovery. Gate: type-check plus behavioral regressions; browser tests explicitly pending if runner unavailable.

### Stage C — complete the split (next, after source recovery)
Establish one shared versioned domain model and a browser capability registry. Port timetable/Calendar, Study OS, Gmail state and Gleam as full modules with lazy entrypoints. Extension retains Chrome powers; dashboard owns planning UI. Gate: cross-surface parity matrix, account pairing, deletions, offline/restart and migration tests. Do not add another parallel copy of each store.

### Stage D — measured release
Clean/upgrade Chrome profiles, real account OAuth lifecycle, provider denial/rate limits, two tabs/two devices, 320px/200% zoom/keyboard/screen-reader, 30-minute memory trace and target Mac acceptance. <=300MB remains a target measured for a defined dashboard scenario, not a promise across arbitrary AI models or Chrome processes.

### Stage E — controlled evolution
Periodic read-only tests/research, versioned findings, benchmarked model candidates and release proposals. Changes pass regression/type/build/security/data-migration checks and review before publication. Pin tested dependencies; maintain rollback and migration recovery. No unattended permission expansion, paid service activation, destructive cleanup or self-modifying production agent.

## Definition of completion

Completion means a agreed, bounded release scope passes explicit tests. It does not mean every possible future feature exists or every defect is mathematically impossible. No defensible replacement percentage is available until the extension is inspected and each capability is counted against a consistent acceptance rubric.

## Post-repair results

### Implemented in this pass

- A single per-page saving coordinator replaces the overlapping autosave effect. Outstanding request acknowledgements cannot erase newer pending edits. Initial loads preserve edits typed while waiting. Conflicting notes retain both versions and stop automatic saving until a choice is made.
- Failed saves have visible status, retry, plaintext recovery export and a close-page warning. This is **not durable offline storage**: a crashed browser can still lose an unsent draft.
- API writes are bounded before parsing, require a real snapshot/revision and reject duplicate IDs/invalid dates. Corrupt saved JSON or core shape fails closed. Account identity remains server-checked, query values are bound, and compare-and-swap is tested against SQLite.
- Anonymous visitors now see a sign-in entry instead of an editable personal dashboard with nonfunctional cloud saving. Existing public/private audience settings are unchanged.
- Browser import now requires read-preview and import approval. Different existing notes and running focus missions are retained. No automatic bridge push is made by the updated dashboard. Extension-side permission/pairing remains unverified.
- Timer pause retains remaining seconds; completion stays at zero; deadline arithmetic handles throttled/background intervals. Reload persistence is still absent.
- Chapter grammar preserves non-contiguous chapter lists and excludes following deadline/duration numbers. Repeated active chapter titles are reused; changing a running mission asks the user to pause first. This does not add full scheduling or textbook automation.
- Panels reuse the installed accessible dialog primitive; labelled inputs, contained close controls, larger targets, wrapping rules, inert Cinema controls and truthful capability labels were added. Real keyboard/visual acceptance remains required.
- Motion preferences affect CSS and canvas, OS preference changes are observed, hidden canvas buffers shrink, Balanced draws at most 24fps, and the idle page clock updates every 30 seconds instead of every second. Theme hues are persisted and propagated to panels. No measured MB or battery reduction is claimed.
- Weather responses validate temperature, have a fetch timeout and can be refreshed. The weather card no longer claims to drive adaptation that is not implemented.
