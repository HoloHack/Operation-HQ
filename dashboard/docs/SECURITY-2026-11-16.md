### Compiled decoder promotion gate — follow-up

Installed package versions alone are insufficient because plugin-rsc can alias its vendored decoder to the project's package. The build-only `ohq:bundled-rsc-proof` Vite plugin now examines the **included output chunk module graph** for every written environment, resolves each Flight decoder's actual owning package, rejects any version outside the reviewed `19.2.9`/`19.3.1` set, and requires an included server decoder in the production RSC output. Reference-analysis passes with `write=false` are deliberately excluded: plugin-rsc strips runtime code during those scans. This is a build gate, not an application endpoint or a production metadata disclosure.

A fresh bounded production build on the candidate resolves:

- RSC output: project `react-server-dom-webpack@19.2.9`, `client.edge.production.js` and `server.edge.production.js`.
- Browser output: project `19.2.9`, `client.browser.production.js`.
- SSR output: project `19.2.9`, `client.edge.production.js`.
- The installed plugin's `19.3.1` vendor remains separately pin-tested but is **not** the decoder included by this build. Do not substitute the installed vendor version for compiled provenance.

The proof JSON is produced at `.sites-runtime/security-proof/{rsc,client,ssr}.json`, with environment, actual source package/version, package-relative filename and SHA-256 of that source decoder. Paths contain no owner identity or credentials. The RSC server source hash was `b47608e656b07f291c4f1fe7b92dee4351a5e3d661953e82e6f53b7e9abb691c`; this is source-module provenance from the compiled graph, not a hash of the final transformed deployment bundle. Build logs also print resolved versions. Tests reject vulnerable/unknown fixtures and a decoder that is installed but absent/tree-shaken from output. Retain matching fresh CI build logs/proof plus production SSR/hydration checks before promotion.
