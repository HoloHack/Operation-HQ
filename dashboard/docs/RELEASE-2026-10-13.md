# Operation HQ planning and release radar

Candidate based on published Site source c64a067 and GitHub main 74357e8. No production account was used for tests.

## Delivered scope

- Explicit, revocable browser pairing and automatic planning exchange every 30 seconds while the dashboard is visible. Exact deployed origin, protocol validation, token/account association, shared mutation lock, bounded revision history and conflict abstention. Tasks and notes mirror into native tools; rich planning metadata is retained in the shared canonical document. Imported browser recurrence and timetable definitions keep their browser owner: changes to these definitions must be made in that tool, then synchronized.
- Deletion tombstones prevent stale cloud snapshots from resurrecting removed records. Old schema-1 account rows gain optional fields without a database migration. Old clients must reload before editing new release/tombstone fields.
- Day, week, month and agenda views; timed and all-day commitments, notes/location, weekly timetable blocks, alternating-week projection from the selected browser profile, local now/next/tomorrow guidance and calendar export.
- Capacity-aware study sessions respect fixed events, all-day commitments, task deadlines, elapsed hours and breaks. All changes require preview/approval. Applying a stale preview stops. Undo removes only its own unedited sessions and preserves unrelated additions.
- Release radar searches AniList, resolves known nicknames, follows exact title editions, checks anime airing metadata and supported VIZ chapter pages, counts down only evidenced dates, marks caught-up state, keeps last verified data on errors and supports a user-entered announcement date with a source link.
- Requested names are discovery shortcuts, not fake dated records. Search selects the correct edition. Manga without a supported publisher adapter has no automatic chapter deadline; the UI explicitly says date not announced.
- Tracker refresh policy: six hours normally, one hour near releases, 15 minutes after failure, only while visible. Manual announcement dates remain untouched until automatic checks are resumed. In-app unread notices; no closed-dashboard desktop reminder claim.
- Commands route tasks, unfinished work, calendar/rescheduling, study/exams, release radar, notes, themes and browser tools. The dashboard remains deterministic; no model is silently downloaded or represented as a general-purpose AI.
- Anthropic frontend-design guidance informs the release shelf and planning workbench; purpose-specific layouts, contained controls, restrained response motion and reduced-motion handling.
