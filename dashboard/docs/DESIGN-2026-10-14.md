# Operation HQ: study desk redesign

The purpose is to help a student choose a next action, follow their timetable and begin a focus session. The home screen is a working desk, not a product landing page.

## References and choices

Compared [Vanszs/Anti-AI-UI](https://github.com/Vanszs/Anti-AI-UI/blob/main/Anti-AI-SLop/SKILL.md) and [Krirox/anti-ai-slop-skills](https://github.com/Krirox/anti-ai-slop-skills/blob/main/SKILL.md). Read both complete skills. Applied Krirox's hierarchy, specificity, restraint and aesthetic commitment as the primary review guide, with Vanszs's component/a11y checks. These are design references, not installed runtime packages. No third-party code or font was copied.

The baseline source rubric was 12/30 (subjective, not a usability benchmark). Its worst issues were glow/glass across every surface, repetitive card weight and undersized metadata. The replacement is an editorial study desk with warm paper or dark ink, system serif display type, one user-chosen accent and readable text navigation. Existing approved accent colours remain intact; new accounts begin with leaf green.

- Home prioritises the next task; Focus has a quieter independent surface. Today and task lists use rules rather than an identical card grid. DOM order follows the visual reading order.
- Paper/Night is an account-scoped device preference. No new cloud schema or model download. The standard Paper/Balanced screen allocates a 1x1 decorative canvas; no animation loop runs. Full Night/Cinema can show the existing bounded ambient field. Hidden tabs still stop drawing.
- Scene changes have layered page-turn motion, with pointer-transparent overlays and OS/app Reduced Motion. Most controls use short colour/border feedback rather than moving their hit targets.
- Dialogs retain Radix focus management, Escape and contained 44px close buttons. Inputs have labels and 12–14px internal padding. Calendar has a dedicated horizontal scroll region. At small widths navigation becomes a scrollable bottom bar.
- Commands has visible examples, a native suggestion list, a header entry and Cmd/Ctrl-K. It remains a deterministic local tool router; neither arbitrary reasoning nor fabricated textbook chapter navigation is claimed.

## Functional gaps closed

- Task title, subject, priority, deadline and effort editing; active/done/all views; search; recoverable deletion. Stale editors stop instead of overwriting externally changed records. Undo timestamps advance past deletion markers even after clock skew.
- Local weekly block editing, timetable-inclusive 30-day Agenda and clean event-composer reset. Imported rich recurrence/profile definitions remain owned by their companion editor.
- Maths aliases receive the intended scheduling priority. A chapter rescheduling command first collects a deadline and estimate, then opens the real Calendar preview. Mail, Weather, Help and Pause commands map to actual actions; unsupported input is inert.
- Study rescheduling retains historical, active and out-of-window sessions. Its inverse preserves unrelated work and stops if a generated event changed.
- Tombstone lookups now use an indexed map instead of a scan for each record. This reduces worst-case merge work; no measured total-RAM claim follows from that change.

## Validation and release gate

Local regression suite: 67 passing at this stage. TypeScript and production build were checked. Expanded native-Chrome acceptance source adds task edit/delete/undo, weekly edit/Agenda, Maths scheduling and Paper/Night persistence/responsive checks to the existing 16 journeys. Actual CI outcomes must be recorded before claiming that browser acceptance passed.

The native cloud browser reached the published sign-in surface; private workspaces require a signed-in session. CI uses the actual dashboard component, real Chrome companion, IndexedDB and Web Locks in disposable profiles. Cloud account/provider replies are isolated fixtures. Production personal records are not test fixtures.

## Deliberate limits

This is not whole-roadmap completion. Full Google Calendar recurrence exceptions/time-zone/import/provider parity, subtasks/dependencies, dashboard ports of Gleam/Recall/Gmail, general-purpose model-backed intelligence, authenticated Cambridge navigation, closed-dashboard release notices, real provider OAuth and target-Mac total memory/frame pacing still need their own acceptance work. Bookmark protections are unchanged; semantic classification still abstains on ambiguous material. No claim of perfect categorisation or <=300MB is made.

Rollback is Site version 5 plus the prior GitHub commit. No dependency, database migration, OAuth scope or provider permission change is needed. Data created in the newer UI remains in the same canonical store; disconnect pairing and export planning before reverting to an older client.
