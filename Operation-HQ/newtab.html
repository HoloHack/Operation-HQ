                                                Paid Services

                                                Everything on this tab requires your own account and your own billing elsewhere — nothing here is free, and nothing runs without you supplying a key. Kept in one place on purpose, separate from the free integrations tab, so it's always obvious which features can quietly cost real money.

                                                Claude API Key (Daily Plan)

                                                Powers Today's Plan. Your key is stored only in this browser and calls the API directly — never published or shared this build with the key still in it. Get one at console.anthropic.com. Costs a small amount per generation (roughly a cent).

                                                ElevenLabs API Key (Read Plan Aloud)

                                                Adds a "Read it to me" button to Today's Plan that speaks the plan rationale out loud. Free tier exists (~10,000 characters/month at time of writing — check elevenlabs.io/pricing, this changes) but is still a metered, paid-above-that account, so it lives here rather than in the free Integrations tab. Without a key, the button simply doesn't appear.

                                                Local AI (offline, private, zero cost)

                                                Runs Llama 3.2 1B directly in this tab via WebGPU. It can summarize, explain, extract actions, make a quiz, critique a plan, and refine an imported assessment brief. Nothing is sent to an API. The first load downloads roughly 700MB–900MB and the model must be loaded once per fresh tab session.

                                                Research Suggestions

                                                Off by default. When on, this watches Notes, Tasks, and your Capture inbox — never Idea Vault — for a word that keeps showing up across at least 3 separate entries in the last two weeks, and quietly offers a one-click Perplexity search for it near the greeting. Purely local word-matching (no new permission, no data leaves the device unless you click "Research it"), and each topic is suppressed for 7 days after it's shown once, so it can't nag.

                                                Spotify Client ID

                                                Free — register your own app at developer.spotify.com/dashboard (takes about 2 minutes), then add this exact Redirect URI there: (shown once you open the Spotify panel). Requires your own Spotify Premium account to actually play anything — the Web Playback SDK itself is Premium-only, same as the ads/offline distinction elsewhere in this app.

                                                Automation Webhook (Zapier / Make / n8n / anything)

                                                Completely free — this is a plain HTTP POST from your browser, not an API with a key or a cost. Paste any webhook URL (a Zapier "Catch Hook" trigger, a Make.com webhook, an n8n webhook node, anything that accepts a POST) and HQ will fire a JSON payload to it whenever today's plan finishes generating: {"event":"plan_generated","date":"...","taskCount":N,"plannedMinutes":N}. Whatever you build downstream from there (log it to a sheet, ping Slack, whatever) happens entirely on your own automation platform — HQ has no idea what you do with it. Sent fire-and-forget; a failed or missing webhook never blocks or slows down plan generation.

                                                Deep Work — Site Blocking

                                                Sites listed here become completely unreachable (blocked at the network level, before any page content loads) while Deep Work is on — toggle it from the shield icon in the top bar. Turning it off instantly restores access.

                                                Deep Work — Disable JS Instead (lighter option)

                                                For sites you still need reachable but want neutered rather than fully blocked — e.g. Gmail stays open for anything urgent, but its interactive JS (and the scrolling/notifications that come with it) is off. Uses chrome.contentSettings rather than the network-level block above, which comes with a real caveat worth knowing: unlike the full block, there's no guarantee this lands before a page's own inline scripts have already started running, so it's meaningfully less airtight than the block list — a genuinely lighter option, not an equally strong one.
